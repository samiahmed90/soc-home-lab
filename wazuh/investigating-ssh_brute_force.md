# SSH Brute Force Investigation with Wazuh

## Overview

This project demonstrates how Wazuh detects and analyzes an SSH brute force attack against a Linux server. A Kali Linux machine was used to simulate multiple failed SSH login attempts while the Wazuh Manager collected, analyzed, and generated security alerts.

The investigation focuses on identifying:

- Failed SSH authentication attempts
- Invalid username login attempts
- Brute force attack detection
- Source IP address of the attacker
- Wazuh rule IDs triggered during the attack

---

## Lab Environment

| Component | Description |
|-----------|-------------|
| SIEM | Wazuh 4.x |
| Manager | Ubuntu 22.04 |
| Attacker | Kali Linux |
| Protocol | SSH |
| Target | Linux Ubuntu Wazuh Server |

---

## Attack Simulation

A custom password list was created on the Kali Linux attacker machine.

Example passwords:

```
abc1234
123admin
1234567890
vpn123
```

The password list was later used to perform repeated SSH authentication attempts against the Ubuntu server.

Detected events included:

## Investigation

Opening an alert inside Threat Hunting provides detailed forensic information.

Important fields observed:

| Field | Value |
|--------|-------|
| Agent Name | LinuxUbuntuWazuhServer |
| Agent ID | 000 |
| Decoder | sshd |
| Source IP | 192.168.68.112 |
| Username | jaimin |
| Rule Description | Attempt to login using a non-existent user |
| Rule ID | 5710 |

The **Full Log** clearly shows the failed SSH authentication attempt generated by the attacker.

Example:

```
Failed password for invalid user jaimin from 192.168.68.112
```

# Analysis

The attacker repeatedly attempted to authenticate to the SSH service using invalid credentials.

Wazuh correlated the repeated authentication failures and generated multiple alerts, including a high-severity brute force detection rule.

The attack was successfully identified without any successful login occurring.
